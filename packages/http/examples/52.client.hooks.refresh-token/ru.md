# Обновить просроченный токен

[English version](en.md)

Клиент начинает с просроченным токеном. На 401 он заново входит через `POST /login`, запоминает новый токен и повторяет
запрос. Каждая вкладка возвращает имя из `GET /me`.

<!-- @variants -->

## В чём разница

- **jext** подписывает каждый запрос в хуке `beforeRequest`; хук `afterResponse` видит 401, получает новый токен и
  возвращает ответ повторного запроса.
- **axios** делает то же перехватчиками запроса и ответа; флаг `retried` в конфиге не даёт уйти в бесконечный цикл.
- **ky** повторяет запрос из `afterResponse`, возвращая `ky.retry({ request })` с новым заголовком.
- **ofetch** повторяет 401 через `retry: 1` и `retryStatusCodes: [401]`; `onResponseError` обновляет токен перед
  повтором, а `onRequest` подписывает его.
- **fetch** и **XMLHttpRequest** проверяют статус в `api()` и сами отправляют запрос ещё раз.
