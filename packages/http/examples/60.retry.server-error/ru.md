# Повторить запрос после ошибки сервера

[English version](en.md)

`GET /flaky` дважды отвечает 503 и удаётся с третьей попытки. Сервер считает попытки по `key`, поэтому каждая вкладка
отправляет свой ключ и возвращает номер удачной попытки.

<!-- @variants -->

## В чём разница

- **jext** повторяет через `.retry({ limit, delay })` (или `.retry(2)`): GET, HEAD, PUT, DELETE и OPTIONS, статусы 408,
  429, 500, 502, 503 и 504 и оборванные соединения, но не таймаут и не отмену. Пауза удваивается: по умолчанию 300 мс,
  600 мс… Без явной просьбы ничего не повторяется.
- **ky** повторяет по умолчанию: 2 раза, те же методы, TRACE и QUERY, ещё и на 413, с паузой 0,3 с, удваивая её. Урок
  сокращает паузу до 100 мс.
- **ofetch** по умолчанию повторяет GET один раз без паузы, а POST, PUT, PATCH и DELETE никогда; `retry` и `retryDelay`
  это меняют. В его списке статусов есть ещё 409 и 425.
- В **axios** нет повторов (их добавляет пакет axios-retry), поэтому они написаны вручную, как для **fetch** и
  **XMLHttpRequest**. Ручные версии здесь повторяют только статусы, но не оборванное соединение.
