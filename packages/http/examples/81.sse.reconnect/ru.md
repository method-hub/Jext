# Продолжить поток после обрыва

[English version](en.md)

`GET /ticker` присылает событие `1` и обрывает соединение. Переподключение с `Last-Event-ID: 1` получает события `2` и
`3`, и поток завершается. Каждая вкладка возвращает данные всех трёх событий.

<!-- @variants -->

## В чём разница

- **jext** переподключается через `.reconnect({ retries, delay })` (или `.reconnect()` без предела): ждёт, отправляет
  `Last-Event-ID` с последним id и берёт паузу из `retry:`, если сервер её прислал. Конец потока завершает цикл;
  `retries` считает обрывы подряд.
- У **fetch**, **XMLHttpRequest**, **axios**, **ky** и **ofetch** нет переподключения: урок хранит события, после обрыва
  снова открывает поток и сам отправляет `Last-Event-ID`.
- `EventSource` в браузере переподключается сам и отправляет `Last-Event-ID`, но переподключается и после обычного
  завершения, и годится только для GET без своих заголовков.
